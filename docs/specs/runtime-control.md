# Runtime 控制规格

- Api2Business 是账号、上游、评分、调度、错误诊断和经营核算的唯一控制入口；运行面和
  配置边界见 [Api2Business 技能](../../skills/api2business/SKILL.md)。
- owning YAML 是运维事实来源。V2 的作用域、功能开关、周期、模型白名单和模板文件由
  YAML 定义，代码只负责校验、渲染和执行。
- V2 是当前上游调度运行面；Codex、Claude、Grok 使用同一作用域接口，旧全局调度配置
  不得兼容复活。
- Web、CLI、HTTP API 和 Worker 复用同一领域服务；HTTP 只校验并受理长流程，Worker
  执行长流程，数据库读取统一经过应用内排队 broker。
- 普通读取可以命中持久化读模型缓存；过期时先返回陈旧快照并后台刷新，重建失败保留上一份
  成功快照。缓存状态不能替代业务终态。
- Web 会话失效后，上游调度 V2 收到本产品 API 的 `401` 时立即进入 `/login`。
  - 初始加载、手动或自动刷新、分页读取遵循相同规则。
  - 跳转先于响应正文解析，非 JSON 的 `401` 也能触发。
  - `403`、网络错误和普通服务失败保留对应错误语义，不能冒充登录失效。
  - 普通刷新失败仍保留上一份成功快照；认证失败不能被该容错规则吞掉。
- 会话失效取证复用正式截图 CLI。
  - 可显式创建比部署配置更短的独立验收会话，保持同一 origin 和原生认证语义。
  - 不修改部署会话期限，不撤销或替换既有用户会话。
  - 浏览器仅连续采集截图，认证事实通过正式 API 与原始诊断核对。
- 所有真实写入必须经历计划、显式确认、执行、最终回读四步；HTTP 200/202、对象创建成功、
  工作流 running 或页面提示都不能单独证明完成。
- 错误诊断区分全局路由失败、已选上游账号失败、已观测切号、输出后抑制、客户端断开和
  成功记录关联；No available accounts 只有在已有账号 ID 且阶段为上游时才进入账号
  切号模板，全局选号失败不套账号模板。
- 错误详情按当前请求关联，未知原因保持未知；切号模板是否命中、流式错误是否绕过模板，
  只见 [上游与调度](../../skills/api2business/references/upstream-scheduling.md)。
- 本规格不复制 CLI 参数、状态机或评分算法；其他文档只交叉引用当前权威。
