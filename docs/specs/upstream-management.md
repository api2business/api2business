# 上游管理规格

- 上游创建、调整、充值、额度、用量、质量和调度信息收敛到同一管理入口。
- 同一钱包的多 API Key 创建与充值必须区分账号作业和钱包账本，充值不可因 Key 数量重复记账。
- 探测倍率写回使用原生批量更新并通过排队读取回读，失败不重建已创建账号。
- 创建和调整支持后缀、成本倍率、并发、优先级和分组。
- 探活隔离的成员并集是当前分组、owning YAML 默认分组和该账号的私有探活分组。
- 用户指定的业务分组与该并集不一致时，终态是用户指定的业务分组加上该私有探活分组。
- 操作顺序、模板回读和优先级副作用只见
  `skills/api2business/references/upstream-scheduling.md`。
- API key 不进入日志、响应、账本、URL 或命令参数。
- 充值记录人民币成本；剩余额度作为资产参与经营核算。
- 额度、状态和质量采样持久化；额度监控的缓存、刷新、可用比例和验收规则统一见
  `skills/api2business/references/quota-monitoring.md`。
- 额度监控的 24 小时实际成本公式、销售倍率折回和缺失处理只以该文档为准。
- 上游调用并发执行，数据库读取仍通过排队通道。
- 自动调度使用质量、成本、余额和探索的纯权重计划，不增加隐式门槛。
