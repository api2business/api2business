# 账号评分规格

- 评分只反映服务质量，不因样本数量少直接扣分。
- 可靠性只计算最终用户可见结果，排除以下样本：
  - 内部 failover；
  - 非业务端点；
  - 额度不足；
  - `model_not_found`、`model_no_found`、模型不存在和无可用模型渠道等模型路由错误。
- 延迟、成功率、错误率和恢复率使用同一时间窗口与衰减权重。
- 池级综合质量与账号级评分使用独立策略，修改池级口径不得改变账号级口径。
- 池级错误证据必须复用综合质量的最终事件窗口：按 `request_id` 去重、排除探针和
  failover 中间事件，并锁定持久化采样时间；默认展示计分失败，同时支持查看已排除和全部错误。
- 错误分页表必须同时展示 `requested_model` 回退后的模型、记录状态码、上游状态码、
  入站/上游端点和上游错误正文；不得返回 API key 或请求头。
- 自动调度先读取评分事实，再生成可审阅计划，确认后批量写入并回读。
- 自动轮次有界超时；失败跳过本轮，不阻塞下一轮。
- 评分使用统一 PostgreSQL 快照：
  - API 和 Worker 按稳定快照键共享同一份成功载荷；
  - 默认每 5 分钟刷新一次；
  - 刷新成功后原子替换快照；
  - 刷新失败只记录错误，继续展示上一份成功快照；
  - 页面首次打开、进程重启和刷新期间均优先展示持久化快照。
