# 金额与币种展示规格

## 判定原则

- 币种由数据来源和实际换算决定，不由页面、供应商名称或符号决定。
  - 美元原值显示 `$` 或“美元”，人民币金额显示 `¥` 或“人民币”。
  - API 美元表示按 API 价格计量的额度或产出，不等于人民币采购支出。
  - 更换符号不能代替换算；只有已应用明确人民币估值规则的结果才显示人民币。
  - 钱包估值按 owning 配置的人民币/API美元倍率计算，不套用统一外汇汇率。
  - 未知与真实零分别显示；币种纠正不得改写账本、余额或历史采样数值。

## 页面口径

| 页面或数据 | 来源与换算 | 展示单位 |
| --- | --- | --- |
| V2 与上游账号余额估值 | 服务端按钱包估值规则换算的 `accountBalanceCny` | 人民币 |
| V2、上游与 OAuth 的 API 产出、消耗额度、剩余预期 | `apiAmountUsd`、`consumedApiAmountUsd`、`remainingExpectedApiAmountUsd` 等 | API 美元 |
| API 产出与消耗速率图、指标及提示 | `sampleApiAmountUsdPerHour`、`rollingApiAmountUsdPerHour` 等 | API 美元/小时 |
| 钱包汇总、可调度余额、质量资产与余额趋势 | 已按钱包估值规则换算的 `remainingCny`、`totalRemainingCny` 等 | 人民币 |
| 上游实际支出及巡检成本 | 完成供应商倍率及人民币估值换算的 `consumedCny`、`totalCostCny` 等 | 人民币 |
| 上游与 OAuth、BugTeam 单位成本 | `costRateCnyPerApiUsd`、`cnyPerApiUsd` 等 | 人民币/API美元 |
| 用户用量、用户余额与抽奖额度 | 标准 API 美元用量、`balanceUsd`、`prizeAmountUsd` | 美元 |
| 用户实际充值、采购退款、上游充值、经营收支及预算 | 人民币交易或账本中的 `*Cny` | 人民币 |

- 同一页面可同时出现上述单位，表头、指标辅助文字和图表提示必须与实际值一致。
  - V2 账号余额的展示和排序均使用人民币估值，与页面上方钱包汇总保持同一换算口径。
  - 原始美元额度保留在数据层，不在人民币余额缺失时直接改符号或作为同列回退值。
  - 单位成本的分子是人民币，分母是 API 美元，不得仅写成美元金额。
  - 负余额及小额欠费精度继续遵循
    [额度监控](../../skills/api2business/references/quota-monitoring.md#数据口径)。

## 复核与验收

- 先从 API 字段追到来源或换算公式，再核对页面值、符号、表头、图表及悬停提示。
  - 使用不为一的估值倍率，避免人民币值和美元值恰好相同而掩盖错误。
  - 验证正值、真实零、未知和小额负余额，不能因修正币种丢掉欠费事实。
- 回归应验证真实渲染出的金额及单位。
  - 不保留“整页禁止美元”或“所有金额统一人民币”的陈旧断言。
  - 页面与模块资源版本一起更新，正式入口截图确认实际加载的新展示。
